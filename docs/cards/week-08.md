## 卡片清单（快速浏览 / 打印）

### 1. ReAct 与 Plan-and-Execute 的核心区别？

**答**：ReAct 边走边想，每一步依赖上一步观察，灵活但容易跑偏、步数多；Plan-and-Execute 先出完整计划再执行，全局性强、可并行、可审查，但计划错了整条链都错。实践常用混合：先粗计划，执行中允许重规划。

<small>标签：范式 · ID：w8-c1</small>

### 2. Reflexion（反思）机制是什么？代价是什么？

**答**：任务失败后，让模型对轨迹做自我批评，把批评写进下一轮上下文再重试。收益：对可验证任务（代码、数学）提升明显。代价：token 与延迟翻倍，且对「不可验证」任务容易自我强化错误。要设最大反思轮数。

<small>标签：范式 · ID：w8-c2</small>

### 3. 工具设计的五条原则？

**答**：① 单一职责、语义清晰；② 描述里写清何时用/不用；③ 参数少而明确，用枚举代替自由文本；④ 返回结构化、可截断的结果（避免塞爆上下文）；⑤ 错误信息要可被模型理解并纠正（而不是堆栈）。

<small>标签：工具 · ID：w8-c3</small>

### 4. MCP 是什么？它解决什么问题？

**答**：Model Context Protocol：把「工具/资源/提示」的提供方式标准化，让 Agent 客户端（IDE、聊天应用）通过统一协议发现和调用外部能力，而不必为每个工具写适配。解决的是工具接入的 N×M 问题，类似 AI 世界的 USB-C。

<small>标签：协议 · ID：w8-c4</small>

### 5. 什么时候 workflow 比 agent 更好？

**答**：任务步骤可枚举、结果要求稳定、成本敏感、需要强可测性时，用 workflow（代码编排 + 局部 LLM 调用）。Agent 的价值在「步骤无法预先确定」。很多生产系统是「workflow 骨架 + agent 节点」，而不是纯 agent。

<small>标签：范式 · ID：w8-c5</small>
