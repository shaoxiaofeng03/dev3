## 卡片清单（快速浏览 / 打印）

### 1. 为什么 RAG 的权限过滤必须下推到检索层？

**答**：若先取 top-k 再按权限过滤，用户可能拿到 0 条结果（本该有权限的文档排在被过滤的后面），且存在侧信道泄露（通过「有没有结果」推断内容存在）。下推到检索层可保证返回的 k 条都在权限范围内。

<small>标签：权限 · ID：w6-c1</small>

### 2. 语义缓存的原理和三个坑？

**答**：原理：把 query 向量化，与缓存中的历史 query 比相似度，超过阈值就复用答案。坑：① 阈值太难定，低了答非所问、高了等于没缓存；② 用户/租户/权限不同不能共用；③ 知识更新后缓存必须失效（按文档版本打 tag）。

<small>标签：缓存 · ID：w6-c2</small>

### 3. 多租户在 RAG 里要隔离哪几层？

**答**：① 数据层：文档与块带 tenant_id，检索强制过滤（最基础）；② 索引层：独立集合/分片，避免互相影响性能与召回；③ 资源层：限流、配额、成本归属；④ 配置层：模型、prompt、知识库可按租户定制。

<small>标签：多租户 · ID：w6-c3</small>

### 4. AI 服务限流和传统 API 限流有什么不同？

**答**：AI 请求耗时长、成本高、输出长度不可预知，所以除了 QPS 还要限 token 预算（预扣+结算）；长请求要能取消；流式响应下「已开始输出」的请求不能简单拒绝，要做排队或降级到小模型。

<small>标签：稳定性 · ID：w6-c4</small>

### 5. 降低 RAG 成本的四个杠杆？

**答**：① 减少无效上下文（更好的检索、更小的 k、压缩片段）；② 模型分层（简单问题小模型，难题大模型）；③ 缓存（精确 + 语义）；④ 减少重复计算（embedding 缓存、增量索引、批处理）。每个杠杆都要用评测确认效果不掉。

<small>标签：成本 · ID：w6-c5</small>

### 6. AI 功能怎么做灰度发布？

**答**：按用户/租户灰度，同时把 prompt 版本、模型版本、检索配置都做成可回滚的开关；对比灰度组与对照组的「采纳率/追问率/人工接管率」，而不只是延迟；准备一键回滚到旧配置。

<small>标签：发布 · ID：w6-c6</small>
