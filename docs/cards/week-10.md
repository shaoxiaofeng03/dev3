## 卡片清单（快速浏览 / 打印）

### 1. 多智能体的三种常见协作模式？

**答**：① Supervisor：一个主管拆任务、分派给专家、汇总结果；② Handoff：agent 之间移交控制权（如客服转人工）；③ 辩论/评审：多个 agent 给不同答案，由评审者裁决。生产上最常见的是 supervisor，因为可控、易观测。

<small>标签：多智能体 · ID：w10-c1</small>

### 2. 什么情况下多智能体会是负优化？

**答**：任务简单、上下文可共享、延迟敏感时：多 agent 带来额外通信开销、信息在传递中丢失、错误被放大、成本翻倍。判断标准：子任务是否真的需要不同的工具集/上下文/权限。否则单 agent + 好的工具划分更优。

<small>标签：多智能体 · ID：w10-c2</small>

### 3. Agent 评测和 RAG 评测最大的不同？

**答**：RAG 评的是「答案对不对」，Agent 还要评「过程对不对」：是否选了正确工具、参数是否正确、步数是否合理、有没有多余动作、失败后能否恢复。所以要轨迹级评测（步骤匹配）+ 结果级评测（任务完成）双轨。

<small>标签：评测 · ID：w10-c3</small>

### 4. 怎么给开放任务定义「成功」？

**答**：把成功标准写成可判定的检查项：必须包含的事实、必须调用的工具、必须产出的文件、禁止的动作。LLM-as-judge 可以做初筛，但要抽检校准；关键任务保留人工评分。

<small>标签：评测 · ID：w10-c4</small>

### 5. Agent 可观测的三件套是什么？

**答**：① Trace：每步的输入/输出/工具调用/耗时，可视化时间线；② 指标：成功率、平均步数、工具错误率、P95 延迟、单任务成本；③ 回放：给定 trace 能重放整条链路，用于调试与回归测试。

<small>标签：可观测 · ID：w10-c5</small>
