## 卡片清单（快速浏览 / 打印）

### 1. 自注意力的计算过程和复杂度？

**答**：Q、K、V 由输入线性变换得到；scores = QKᵀ/√d，softmax 后加权求和 V。复杂度 O(n²·d)，n 为序列长度——这就是长上下文昂贵的根源，也是各种稀疏/线性注意力、KV cache 优化的动机。

<small>标签：基础 · ID：w16-c1</small>

### 2. KV cache 是什么？为什么能加速？代价是什么？

**答**：自回归生成时，已计算的 K/V 可缓存复用，避免每步重算整个前缀。代价：显存占用随序列长度和层数线性增长，长上下文时成为瓶颈（于是有 PagedAttention、量化 KV、滑动窗口等优化）。

<small>标签：推理 · ID：w16-c2</small>

### 3. 量化和投机采样分别优化什么？

**答**：量化：把权重/激活从 FP16 降到 INT8/INT4，减少显存与带宽，提升吞吐，代价是精度损失（需校准）。投机采样：用小模型先草拟多个 token，大模型一次并行验证，提升解码速度，输出分布不变。

<small>标签：推理 · ID：w16-c3</small>

### 4. MoE（混合专家）的基本思想？

**答**：用多个专家网络 + 路由门控，每个 token 只激活少数专家，从而在总参数量很大时保持较低的计算量。挑战：负载不均衡、通信开销、训练稳定性、显存占用（所有专家都要驻留）。

<small>标签：基础 · ID：w16-c4</small>

### 5. 「上下文工程」和 prompt 工程的区别？

**答**：prompt 工程关注「怎么措辞」；上下文工程关注「往窗口里放什么、按什么顺序放、放多少」——检索结果、工具输出、记忆、历史、指令的编排与预算分配。上下文窗口变长后，瓶颈从「写 prompt」变成「管理上下文」。
