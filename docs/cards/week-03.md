## 卡片清单（快速浏览 / 打印）

### 1. embedding 是什么？为什么能实现语义检索？

**答**：把文本映射成高维向量，语义相近的文本在空间中距离近。模型在大量语料上训练过「同义/上下位/相关」关系，所以「怎么请假」能命中「年假申请流程」，即使字面不重合。

<small>标签：向量 · ID：w3-c1</small>

### 2. 余弦相似度和点积怎么选？为什么要归一化？

**答**：向量归一化后，余弦相似度与点积排序等价。余弦只看方向、不受长度影响，适合文本；点积受模长影响。工程上统一归一化 + 内积，性能更好、结果一致。

<small>标签：向量 · ID：w3-c2</small>

### 3. 中文场景选 embedding 模型要考虑什么？

**答**：中文/中英混合效果、最大输入长度、维度（存储与检索成本）、是否支持稀疏向量（混合检索）、部署方式（API 还是本地）、是否可微调。换模型必须重建索引，所以一开始就要留好抽象层。

<small>标签：向量 · ID：w3-c3</small>

### 4. 为什么说「切分决定检索质量的上限」？

**答**：检索的最小单位是 chunk。切得太碎，语义不完整、答不出；切得太大，噪声多、稀释相似度、浪费上下文。切分错了，后面换再好的模型和 rerank 也救不回来。

<small>标签：切分 · ID：w3-c4</small>

### 5. 父子块（small-to-big）检索是什么？解决什么问题？

**答**：用小块做向量检索（精准命中），命中后返回其父块（更大上下文）给模型。解决「小块检索准但信息不全、大块信息全但检索不准」的矛盾。实现：块存父子 id，检索后按父 id 回表。

<small>标签：切分 · ID：w3-c5</small>

### 6. overlap 的作用和副作用？

**答**：作用：避免句子/段落被切断导致语义丢失，跨块信息能被相邻块覆盖。副作用：索引膨胀、重复召回、成本上升。经验：overlap 取块长的 10%–20%，优先按结构（标题/段落）切而不是硬切。

<small>标签：切分 · ID：w3-c6</small>

### 7. 选向量库主要看哪几个维度？

**答**：① 部署（托管/自建、是否要 Docker/K8s）；② 检索能力（元数据过滤、混合检索、多向量）；③ 规模与性能（百万级还是十亿级）；④ 运维与成本；⑤ 生态（LangChain/LlamaIndex 支持）。本项目默认 Chroma（pip 安装、零运维）；生产上 pgvector（少一个组件）或 Qdrant（能力强）也常见。

<small>标签：向量库 · ID：w3-c7</small>

### 8. 为什么元数据过滤必须在检索时做，而不是检索后过滤？

**答**：检索后再过滤会导致「top-k 里大量不合法结果被删掉」，实际可用结果变少甚至为空。带 filter 的向量检索是在候选集内搜索，能保证返回 k 条合法结果。权限、租户、时间范围都应下推到检索层。

<small>标签：向量库 · ID：w3-c8</small>

### 9. top-k 为什么不是越大越好？

**答**：k 越大：召回率上升但精确率下降，噪声挤占上下文、增加 token 成本与延迟，还可能让模型被无关片段误导。通常先 k=10~20 粗排，再 rerank 取 3~5 给模型。

<small>标签：检索 · ID：w3-c9</small>

### 10. BM25 和向量检索为什么互补？

**答**：BM25 靠词频/逆文档频率，对专有名词、型号、错误码、精确短语极强，但不理解同义改写；向量检索理解语义，但对罕见实体和精确匹配不敏感。混合检索（如 RRF 融合）能同时覆盖两类查询。

<small>标签：检索 · ID：w3-c10</small>

### 11. rerank 的作用是什么？和向量检索有什么区别？

**答**：向量检索是「双塔」式的粗排，query 和 doc 分别编码，快但精度有限；rerank 是 cross-encoder，把 query 和 doc 拼一起打分，精度高但慢。所以：粗排召回 20–50 条 → rerank 精排取 top 3–5。

<small>标签：检索 · ID：w3-c11</small>

### 12. RAG 回答里怎么做引用和拒答？

**答**：引用：给每个片段编号，要求模型在句末标注 [1][2]，前端可点击溯源。拒答：明确指令「只能依据给定片段回答，证据不足就说不知道并说明缺什么」，并在检索分数低于阈值时直接拒答，不要硬生成。

<small>标签：生成 · ID：w3-c12</small>
