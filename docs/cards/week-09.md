## 卡片清单（快速浏览 / 打印）

### 1. Agent 的三类记忆分别是什么？

**答**：① 短期（工作记忆）：当前会话的消息与中间结果，放上下文窗口；② 长期（语义记忆）：用户偏好、事实、领域知识，存外部库按需检索；③ 情景记忆：历史任务轨迹，用于 few-shot 复用与复盘。三者的写入时机与检索方式都不同。

<small>标签：记忆 · ID：w9-c1</small>

### 2. 上下文压缩的常用手段和风险？

**答**：手段：滑动窗口、摘要（rolling summary）、关键事实抽取、检索式记忆。风险：摘要丢失细节（数字、约束、否定语义）、摘要偏差被反复放大。缓解：保留原始消息可回查，只压缩「已完成」部分。

<small>标签：记忆 · ID：w9-c2</small>

### 3. checkpointer 在 Agent 系统里的作用？

**答**：每一步执行后把状态（消息、工具结果、计划、变量）持久化到存储，用 thread_id 关联。作用：进程崩溃可恢复、支持长任务暂停/续跑、支持人工审批后继续、支持回放调试。无状态的 Agent 只能算 demo。

<small>标签：状态 · ID：w9-c3</small>

### 4. human-in-the-loop 的介入点应该设在哪？

**答**：设在「不可逆或高成本」的动作前：写库、发消息、付款、删除、对外承诺；以及「置信度低」时主动求助。设计要点：超时策略、审批人是谁、拒绝后如何继续、审批记录可审计。

<small>标签：编排 · ID：w9-c4</small>

### 5. 长期记忆怎么写才不会污染回答？

**答**：① 写入前做事实抽取与去重，带来源与时间；② 区分「用户说的偏好」与「模型推断」，后者置信度低；③ 检索时按相关性与时效排序，并给模型标注来源；④ 支持用户查看与删除（合规要求）。
