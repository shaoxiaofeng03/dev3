# 怎么用这套站点

这套站点的定位不是「教程库」，而是**作战面板**：每天打开就知道做什么，做完能勾掉，周末能复盘。

## 每天（10 分钟维护）

1. 打开 [打卡页](/checkin) 或首页的「今天」区块。
2. 按顺序勾掉今天的任务（工作日 3–4 条，周末 4–7 条）。
3. 学完在当天学习页底部「今日记录」发一条：收获 / 卡点 / 想法，可以追加多条。
4. 晚上睡前用 4 分钟过一遍当天记忆卡：打开本周的记忆卡页，点「今天到期」。

> 每天 2 小时里，最后 25 分钟就是留给记忆卡的。不要攒到周末一起背。

## 学习文档

每天/每周的**知识点、阅读顺序、动手清单和自检问题**在「学习」页（`/study/`）：

- **W1–W4**：每天一页，讲义级，先读它再动手。
- **W5–W20**：每周一页，导航级，含 7 天拆分建议和资料。

计划页的「学习」列、首页「今天」区块、每周任务卡右上角都有入口。

## 每周（30 分钟复盘）

周日晚在当周页面做三件事：

- 对照「本周交付」自查，没完成的写清原因（估时不准 / 被打断 / 内容太难）。
- 回答页面底部的「复盘问题」，然后在「本周复盘」块里填三段（最大卡点 / 下周只改一件事 / 本周最值钱认知）并保存；块上方会自动汇总本周所有「卡点」记录。
- 确认下周一开始前，环境和资料都就绪（例如 bge-m3 模型先下载好、依赖先装好）。

## 每月（1 小时校准）

每四周回看一次 [20 周总览](/plan/)：

- 进度落后超过 1 周：砍内容，不要砍项目。项目是简历的核心，笔记和扩展阅读可以砍。
- 进度提前：不要加新内容，把时间投到「项目做得更深」和「算法」上。

## 数据与同步

打卡和复习进度默认只存在当前浏览器。要跨设备，需要配置 GitHub Token（[怎么配](/guide/github-token)），然后在打卡页点「同步到 GitHub」。

**建议的节奏**：平时只勾选（不联网也能用），每周日复盘完点一次同步。这样 commit 记录也很干净，一周一条。

## 想改内容怎么办

站点内容全部由 `plan/` 下的数据源生成，不要直接改 `docs/plan/*.md`（会被覆盖）。

```bash
# 1. 改 plan/weeks-01-04.mjs、plan/weeks-05-20.mjs 或 plan/study-*.mjs
# 2. 重新生成页面
npm run content
# 3. 本地预览
npm run dev
```

数据结构说明见 [数据结构说明](/guide/data-format)。

## 常见问题

**页面上的勾选会丢吗？** 不会，除非你清了浏览器数据。重要节点建议点一次「导出 JSON」存到网盘。

**为什么任务勾选后热力图没变？** 热力图按「任务所属日期」统计，不是按你点击的日期。周末补做周三的任务，会记在周三。

**本地 `npm run dev` 打开是空白？** 先确认已经跑过 `npm run content`（`npm run dev` 会自动跑），并检查 `docs/data/plan.json` 是否存在。
