### Plan-and-Execute 与 ReAct

ReAct 边走边想，灵活但容易跑偏、步数多；Plan-and-Execute 先出完整计划再执行，全局性强、可审查，但计划错了整条链都错。

实践常用混合：先粗计划，执行中允许重规划。

### 反思的收益与代价

对可验证任务（代码、数学）提升明显；对不可验证任务容易自我强化错误。

token 与延迟会翻倍，必须设最大反思轮数。

### MCP 解决什么

把工具/资源/提示的提供方式标准化，让客户端通过统一协议发现和调用外部能力，解决工具接入的 N×M 问题。

它不是「更强的 Agent」，是接入层的协议。

## 常见坑

- 反思轮数不设上限，成本翻倍还越改越错。
- 计划一旦生成就不再修正，环境变了还硬执行。
- MCP 工具权限给太大，没有白名单。
