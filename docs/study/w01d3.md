### 一、工程化三件套：声明、锁定、落地

Java 里 pom 声明依赖，Maven 解析后下载到 `~/.m2`，classpath 决定运行时能加载哪些 jar。Python 把这三件事拆成了三个东西，并且多了一层「每个项目一个解释器环境」。

### 1.1 三件套的数据流

把这条链记住，后面所有「为什么装不上 / 为什么版本不对」都能从链上定位：

- `pyproject.toml`：声明「我要什么」，类似 pom 的 `<dependencies>`，本身不安装任何东西。
- `uv.lock`：锁定「最终是哪个版本、从哪来、hash 是多少」，同事和 CI 装出来和你完全一致。
- `.venv/`：落地「本项目的解释器和已装依赖」，可随时删除重建，**不进 git**。
- uv 全局缓存（`~/.cache/uv`）：真正共享的下载缓存，≈ `~/.m2/repository`，第二次装同一个包几乎不下载。
- `sys.path`：运行时真正扮演 classpath 的角色；`.venv` 只是让解释器自动把它加进 `sys.path`。

### 1.2 pyproject.toml 里只要看懂五块

下面是本项目的完整配置，字段都已标注；其余字段（authors、readme、license）不影响今天的目标。

```toml
[project]
name = "hello-world"
version = "0.1.0"
requires-python = ">=3.13"            # 允许的解释器版本范围

dependencies = [
    "httpx>=0.28",                     # 等价于 pom 的 <dependency>
]

[project.scripts]
hello-world = "hello_world.cli:main"   # 命令名 → 包.模块:函数

[build-system]
requires = ["uv_build>=0.13.8,<0.14.0"]
build-backend = "uv_build"             # 打包后端，先当黑盒
```

`[project.scripts]` 最容易忽略：它注册的是一条**真实命令**。装好项目后，终端里的 `hello-world` 就等于调用 `hello_world/cli.py` 里的 `main()`，和 Java 在 manifest 里写 `Main-Class` 是同一类机制。

### 1.3 uv 常用命令：一张表够用

所有命令都在项目根目录执行；`uv run` 会自动向上查找 `pyproject.toml`，找不到才报错。

| 命令 | 做什么 | Maven 类比 |
| --- | --- | --- |
| `uv init --package hello-world` | 建项目骨架（src layout） | `mvn archetype:generate` |
| `uv add httpx` | 改 pyproject + 更新 lock + 装进 .venv | 改 pom 后 `mvn install` |
| `uv remove httpx` | 删依赖并同步三件套 | 删依赖后重新解析 |
| `uv lock` | 只解析并写 `uv.lock` | 无真正对应 |
| `uv sync` | 让 `.venv` 与 `uv.lock` 一致 | `mvn dependency:go-offline` |
| `uv sync --locked` | 声明与 lock 不一致就直接失败（CI 用） | 无真正对应 |
| `uv run <cmd>` | 在项目环境里执行，必要时先 sync | `mvn exec:java` |
| `uv tree` | 打印依赖树 | `mvn dependency:tree` |
| `uv python pin 3.13` | 写 `.python-version` | Maven toolchains |

### 1.4 lock 与 git 的三条纪律

`pyproject.toml` 和 `uv.lock` 都提交；`.venv/` 不提交。clone 下来的人只跑 `uv sync --locked`，不要让他「自己 pip install 一堆」。

`uv.lock` 不要手改。要升级某个包用 `uv lock --upgrade-package httpx`，要全量升级用 `uv lock --upgrade`，然后看 diff 再提交。

CI 里用 `uv sync --locked`：声明和锁不一致就直接失败，避免普通 `uv sync` **悄悄改锁**绕过评审。`--frozen` 更激进，连锁是否过期都不检查，只在明确不需要动锁的场景用；本地开发用普通 `uv sync` 即可。

### 1.5 为什么源码放在 src/ 下

`src/hello_world/` 不在项目根目录，默认不在 `sys.path` 上。`uv sync` 会以 editable 方式把 `hello_world` 装进 `.venv`，于是 `import hello_world` 加载的是源码目录，而不是「碰巧当前目录有个同名文件夹」。

这和 Java 必须把代码打成 jar 才能被别的模块引用是一个道理：先安装，再导入。好处是「本地能跑」和「装完能跑」是同一种状态，测试不会给你假阳性。

```
projects/hello-world/
├── pyproject.toml
├── uv.lock
├── .python-version
└── src/
    └── hello_world/
        ├── __init__.py
        ├── __main__.py
        ├── cli.py
        ├── config.py
        └── http_probe.py
```

### 二、import 到底怎么找模块

先记住一句话：**import 不是编译期链接，而是运行时按路径找文件并执行。** 找的过程只看 `sys.path`，执行的结果缓存在 `sys.modules`。

### 2.1 模块、包、包的入口

一个 `.py` 文件就是模块；带 `__init__.py` 的目录是包。`hello_world` 是包，`hello_world.cli` 是包里的模块。

包被 import 时，`__init__.py` 先执行；它应该保持轻量（版本号、少量导出），不要在里面发网络请求或读配置。

`python -m hello_world` 的完整流程是：先 import 包 `hello_world`（执行 `__init__.py`），再执行 `hello_world/__main__.py`，并把它的 `__name__` 设为 `"__main__"`。

### 2.2 sys.path 随启动方式变化

这是「我这儿能跑、你那儿 ModuleNotFoundError」的第一大来源。注意区别在于**第一个元素**：

| 启动方式 | `sys.path[0]` | 说明 |
| --- | --- | --- |
| `python script.py` | 脚本所在目录 | 不是当前工作目录 |
| `python -m pkg.mod` | 当前工作目录 | 需要 cwd 是项目根 |
| `import pkg` | 不变 | 解释器还会加上 `.venv` 的 site-packages |

`uv run` 不改变这条规则，它只是确保用 `.venv` 里的 python，并在必要时先 sync。想在任意目录运行，就不要依赖 cwd，改用已安装的包或 console script。

### 2.3 顶层代码只执行一次

把下面这段放进 `src/hello_world/__init__.py`，然后连续 import 两次：

```python
# src/hello_world/__init__.py
print("hello_world 被导入了")

__version__ = "0.1.0"
```

```bash
uv run python -c "import hello_world; import hello_world"
# 输出只有一行：hello_world 被导入了
```

第二次 import 直接命中 `sys.modules` 缓存。这就是模块级状态的来源：模块里的变量相当于单例，测试之间会互相污染。

### 2.4 __name__ 与入口 guard

`__name__` 在「直接作为入口执行」时是 `"__main__"`，被 import 时是模块名。注意：`python file.py` 和 `python -m pkg.mod` 都会让目标文件拿到 `"__main__"`，区别不在 `__name__`，而在 `sys.path` 和是否经过包。

```python
# src/hello_world/cli.py
def main() -> int:
    print("真正的主逻辑")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

两种运行结果：

```bash
uv run python -m hello_world.cli   # __name__ == "__main__"，主逻辑执行
uv run python -c "import hello_world.cli"  # __name__ == "hello_world.cli"，主逻辑不执行
```

不写 guard 的后果很具体：别人 import 你的模块（包括 pytest 收集测试、另一个模块复用你的函数）会连带执行主逻辑。`raise SystemExit(main())` 比 `main()` 多做了两件事：把返回值当退出码，并让 `finally` 正常执行。

### 2.5 绝对导入、相对导入、循环导入

项目代码统一用绝对导入：`from hello_world.config import ProbeConfig`。它永远是明确的，挪动文件后也容易搜到。

相对导入 `from .config import ProbeConfig` 只在「模块作为包的一部分被加载」时可用；直接 `python src/hello_world/cli.py` 把文件当顶层脚本执行时，Python 不知道它的父包，会报 `attempted relative import with no known parent package`。这就是推荐 `python -m` 的原因之一。

循环导入（A import B，B 又 import A）通常不是语法问题，而是分层设计问题。按 `config ← http_probe ← cli` 单向依赖组织代码；真遇到时，把公共类型下沉到独立模块，而不是到处写函数内 import。

### 2.6 import 报错排查三步

先确认解释器和路径，再确认包名，最后确认导出名。不要一上来就改代码。

```bash
# 1. 看解释器与搜索路径
uv run python -c "import sys; print(sys.path)"

# 2. 看实际加载到哪个文件（关键一步）
uv run python -c "import hello_world; print(hello_world.__file__)"

# 3. 看包是否真的装进了环境
uv pip list | grep hello
```

| 报错 | 含义 | 优先检查 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named ...` | 路径上找不到模块 | 是否 `uv sync`、cwd 是否是项目根、包名拼写 |
| `ImportError: cannot import name ...` | 模块找到了，但里面没有这个名字 | 导出名拼写、是否忘了定义、是否循环导入 |
| `attempted relative import ...` | 把包内文件当脚本直接跑了 | 改用 `python -m`，或改成绝对导入 |
| `partially initialized module ...` | 循环导入 | 调整依赖方向 |

### 三、异常：把失败当作正常路径

网络代码里，失败是常态，不是意外。异常处理的目标不是「不让程序崩」，而是**让每一层只处理自己能处理的错误，其余带着上下文往上抛**。

### 3.1 异常层次：只记常用的

```
BaseException
├── SystemExit          # sys.exit / raise SystemExit
├── KeyboardInterrupt   # Ctrl+C
└── Exception
    ├── OSError         # IO 错误基类
    │   ├── FileNotFoundError
    │   ├── ConnectionError
    │   └── TimeoutError
    ├── ValueError      # 值不合法（json.JSONDecodeError 是它的子类）
    ├── TypeError       # 类型不对
    ├── KeyError        # dict 键不存在
    └── RuntimeError
```

`except Exception` 不会捕获 `KeyboardInterrupt` 和 `SystemExit`，这是好事：Ctrl+C 永远能打断程序。永远不要写裸 `except:`。

### 3.2 try / except / else / finally 的分工

```python
try:
    resp = client.get(url)
    resp.raise_for_status()
except httpx.TimeoutException:
    ...                      # 只处理超时
else:
    data = resp.json()       # 只有 try 全部成功才执行
finally:
    client.close()           # 无论如何都执行
```

`else` 的价值：把「可能出错的请求」和「成功后的处理」分开，避免把解析错误也误当成请求错误捕获。

捕获顺序必须**子类在前**。`httpx.TimeoutException` 是 `httpx.RequestError` 的子类，如果先写 `except RequestError`，超时分支永远不会生效。

### 3.3 重新抛出要带上下文

```python
try:
    resp = client.get(url)
except httpx.ConnectError as exc:
    raise ProbeError(f"连接失败: {url}") from exc
```

`from exc` 会保留原始异常，traceback 里显示「The above exception was the direct cause...」。丢掉它，线上只能看到一句「连接失败」，不知道是 DNS、TLS 还是代理。

如果只是记录后继续抛，不要用 `raise exc`（会重置 traceback），直接用裸 `raise`。

### 3.4 自定义异常：给调用方一个稳定契约

不要让 httpx 的异常类型泄漏到 CLI 层。定义一个基类，再按「调用方要不要区别对待」拆子类：

```python
class ProbeError(Exception):
    """探测失败的基类。"""


class NetworkError(ProbeError):
    """连不上、握手失败、超时、连接中断。"""


class StatusError(ProbeError):
    """服务器返回了 4xx / 5xx。"""

    def __init__(self, status: int, body: str) -> None:
        super().__init__(f"HTTP {status}: {body[:200]}")
        self.status = status
```

这样 CLI 层只写 `except ProbeError` 就能统一转成退出码；将来做 LLMClient 时，重试层只捕 `NetworkError`，业务层只捕 `StatusError`，职责清楚。

### 3.5 哪些错误值得重试

| 情况 | 可重试 | 处理方式 |
| --- | --- | --- |
| `ConnectTimeout` / `ConnectError` | 是 | 退避后重试，先确认地址是否写错 |
| `ReadTimeout` / `RemoteProtocolError` | 是（仅幂等请求） | GET 可重试；POST 可能已经产生副作用 |
| HTTP 429 | 是 | 优先遵守 `Retry-After`，再指数退避 |
| HTTP 5xx | 是 | 指数退避 + 上限 3 次 |
| HTTP 400 / 401 / 403 / 404 | 否 | 重试只会重复犯错，改请求或改 key |
| `JSONDecodeError` | 否 | 响应格式变了，属于契约问题 |

重试的三个必备要素：最大次数、指数退避 + 随机抖动、只对幂等操作重试。没有上限的重试会把一次故障放大成雪崩。

### 四、类型注解：写给工具看，不写给解释器看

Python 的注解在运行时基本不生效。下面这段不会报错，输出是 `12`：

```python
def add(a: int, b: int) -> int:
    return a + b

print(add("1", "2"))   # 12
```

所以注解的价值在编辑器补全、mypy/pyright 静态检查、以及读代码的人。策略是：**函数签名和数据结构必标，局部变量能推断就不标。**

### 4.1 今天够用的类型写法

| 写法 | 含义 | Java 近似 |
| --- | --- | --- |
| `str` / `int` / `float` / `bool` | 基本类型 | 同名 |
| `list[int]` | 整数列表 | `List<Integer>` |
| `dict[str, list[str]]` | 字符串到字符串列表 | `Map<String, List<String>>` |
| `tuple[int, str]` | 定长元组 | `record` / Pair |
| `str \| None` | 可能为 None（3.10+） | `Optional<String>` |
| `Any` | 放弃检查 | `Object`（但更危险） |
| `Literal["json", "text"]` | 枚举字面量 | enum |
| `Callable[[str], int]` | 函数类型 | `Function<String, Integer>` |

`Any` 会污染整条调用链：一个 `Any` 传进去，后面所有检查都失效。宁可用 `str | None` 明确表达「可能没有」，也不要图省事写 `Any`。

### 4.2 配置用 dataclass

```python
from dataclasses import dataclass, field


@dataclass(frozen=True, slots=True)
class ProbeConfig:
    url: str
    connect_timeout: float = 5.0
    read_timeout: float = 10.0
    headers: dict[str, str] = field(default_factory=dict)
```

三个关键点：`frozen=True` 让配置不可变，避免被调用的函数偷偷改掉；`slots=True` 阻止动态加属性，同时更省内存；可变默认值必须用 `field(default_factory=...)`，直接写 `headers: dict = {}` 会让所有实例共享同一个 dict——和第 2 天默认参数的坑是同一个。

dataclass 自动生成 `__init__`、`__repr__`、`__eq__`，相当于 Java 里手写构造器、`toString`、`equals` 的那堆样板代码。需要转 dict 时用 `dataclasses.asdict(obj)`（注意：`slots=True` 的实例没有 `__dict__`）。

### 五、HTTP 客户端：超时、异常、状态码、可观测

安装：`uv add httpx`。下面是最小可用调用，注意用的是 `Client` 而不是模块级 `httpx.get`：

```python
import httpx

timeout = httpx.Timeout(connect=5.0, read=60.0, write=10.0, pool=5.0)
with httpx.Client(timeout=timeout, headers={"Accept": "application/json"}) as client:
    resp = client.get("https://httpbin.org/get", params={"q": "python"})
    resp.raise_for_status()
    data = resp.json()
```

`Client` 复用连接池和 TLS 会话，批量请求能省掉大量握手时间；`httpx.get(...)` 每次都会新建客户端。做 CLI 或服务时，一个客户端复用到底。

### 5.1 四类超时，分别管什么

| 参数 | 管什么 | 典型值 |
| --- | --- | --- |
| `connect` | DNS + TCP + TLS 握手 | 3–5 秒 |
| `read` | 两次收到数据之间的最大间隔 | 普通 API 10 秒；LLM 60–120 秒 |
| `write` | 发送请求体的时间 | 10 秒 |
| `pool` | 等待连接池空闲连接 | 5 秒 |

两个容易误解的点：第一，`read` 不是总时长，而是「多久没收到新数据」；服务端持续缓慢地吐数据，总时长可以远超 read 超时。第二，httpx 没有内建的「总超时」，需要总时长上限时，异步用 `asyncio.timeout()`，同步在调用方计时并在超时后主动取消。

不传 `timeout` 时 httpx 默认四类都是 5 秒。LLM 调用必须显式把 `read` 调大，否则长回答会被误杀；但也不能不设，没有超时的 HTTP 调用等于埋雷。

### 5.2 httpx 异常分层

```
httpx.HTTPError
├── HTTPStatusError              # raise_for_status() 遇到 4xx / 5xx
└── RequestError                 # 传输层错误的基类
    ├── TransportError
    │   ├── TimeoutException     # ConnectTimeout / ReadTimeout / WriteTimeout / PoolTimeout
    │   ├── NetworkError         # ConnectError / ReadError / WriteError
    │   ├── ProtocolError        # RemoteProtocolError 等
    │   └── ProxyError
    ├── DecodingError
    └── TooManyRedirects

httpx.InvalidURL 直接继承 Exception，不在这棵树里
```

记住基类就够写第一版：传输问题 catch `httpx.RequestError`，状态码问题 catch `httpx.HTTPStatusError`；要细分可重试逻辑时，再按上面的子类判断。

### 5.3 状态码：默认不抛异常

这是 httpx 和很多人预期不同的地方：**4xx / 5xx 默认只是普通响应，不会抛异常。** 必须显式调用 `resp.raise_for_status()`，或自己判断 `resp.status_code`。

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 2xx | 成功 | 解析响应 |
| 301 / 302 | 重定向 | httpx 默认**不跟随**，需要 `follow_redirects=True` |
| 400 | 请求格式错 | 不重试，检查参数 |
| 401 / 403 | 认证失败 / 无权限 | 不重试，检查 key 和权限 |
| 404 | 资源不存在 | 不重试，检查 URL |
| 429 | 限流 | 可重试，优先读 `Retry-After` |
| 5xx | 服务端故障 | 可重试，指数退避 |

### 5.4 重试策略的最小实现

```python
import random
import time

import httpx

RETRYABLE_STATUS = {429, 500, 502, 503, 504}


def should_retry(exc: Exception) -> bool:
    if isinstance(
        exc,
        (httpx.ConnectTimeout, httpx.ReadTimeout, httpx.ConnectError, httpx.RemoteProtocolError),
    ):
        return True
    if isinstance(exc, httpx.HTTPStatusError):
        return exc.response.status_code in RETRYABLE_STATUS
    return False


def backoff(attempt: int) -> float:
    # 0.5s, 1s, 2s, 4s……再乘 0.8–1.2 的随机抖动，避免同时重试
    return min(8.0, 0.5 * 2 ** attempt) * random.uniform(0.8, 1.2)
```

重试循环最多 3 次，每次失败记录 attempt、错误类型、耗时；429 时如果响应头有 `Retry-After`，优先按它等待。POST 请求（尤其是后面调 LLM）不要盲目重试，可能已经扣费或产生了副作用。

### 5.5 可观测：一次请求至少记这六个字段

日志用 JSON 一行，后续接采集系统不用再改格式。字段选择和后面 LLMClient 完全复用：

```json
{"event": "http_request", "method": "GET", "url": "https://httpbin.org/get", "status": 200, "elapsed_ms": 183.4, "request_id": null}
```

`request_id` 从响应头取，不同厂商字段名不同（常见 `x-request-id`，DeepSeek 用 `x-ds-trace-id`，以实际响应头为准）。对账、排障、找厂商支持都靠它。

耗时用 `time.perf_counter()` 而不是 `time.time()`：前者单调递增，不受系统时间调整影响。

### 六、async/await：只要建立正确的心智模型

asyncio 是一个单线程事件循环：协程遇到 `await` 时把控制权交还给循环，循环去跑别的任务，IO 完成后再回来继续。它解决的是「等待」的浪费，不是「计算」的浪费。

```python
import asyncio
import httpx


async def fetch_status(url: str) -> int:
    async with httpx.AsyncClient(timeout=10.0) as client:
        resp = await client.get(url)
        return resp.status_code


async def main() -> None:
    urls = ["https://httpbin.org/get", "https://httpbin.org/status/404"]
    codes = await asyncio.gather(*(fetch_status(u) for u in urls))
    print(codes)


asyncio.run(main())
```

两条纪律：异步函数里不要调用阻塞的 `time.sleep()` 或同步 `httpx.Client`，会把整个事件循环卡住；CPU 密集任务（图像处理、大量计算）用多进程，不是 asyncio。今天会用同步客户端就够了，先把异常、超时、日志写对。

### 7.3 http_probe.py：把 httpx 异常翻译成业务异常

```python
import time
from dataclasses import dataclass

import httpx

from hello_world.config import ProbeConfig


class ProbeError(Exception):
    """探测失败的基类。"""


class NetworkError(ProbeError):
    """连不上、握手失败、超时、连接中断。"""


class StatusError(ProbeError):
    """服务器返回了 4xx / 5xx。"""

    def __init__(self, status: int, body: str) -> None:
        super().__init__(f"HTTP {status}: {body[:200]}")
        self.status = status


@dataclass(frozen=True, slots=True)
class ProbeResult:
    status: int
    elapsed_ms: float
    request_id: str | None
    body_preview: str


def probe(config: ProbeConfig) -> ProbeResult:
    timeout = httpx.Timeout(
        connect=config.connect_timeout,
        read=config.read_timeout,
        write=config.read_timeout,
        pool=config.connect_timeout,
    )
    started = time.perf_counter()
    try:
        with httpx.Client(timeout=timeout, headers=config.headers) as client:
            resp = client.get(config.url)
            resp.raise_for_status()
    except httpx.TimeoutException as exc:
        raise NetworkError(f"请求超时: {config.url}") from exc
    except httpx.RequestError as exc:
        raise NetworkError(f"网络错误: {exc!r}") from exc
    except httpx.HTTPStatusError as exc:
        raise StatusError(exc.response.status_code, exc.response.text) from exc

    elapsed_ms = (time.perf_counter() - started) * 1000
    return ProbeResult(
        status=resp.status_code,
        elapsed_ms=round(elapsed_ms, 1),
        request_id=resp.headers.get("x-request-id") or resp.headers.get("x-ds-trace-id"),
        body_preview=resp.text[:200],
    )
```

### 7.4 cli.py 与 __main__.py：参数、退出码、入口

```python
# src/hello_world/cli.py
import argparse
import json
import sys
from dataclasses import asdict

from hello_world.config import ProbeConfig
from hello_world.http_probe import ProbeError, probe


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(prog="hello-world", description="HTTP 探测工具")
    parser.add_argument("url", help="要请求的 URL")
    parser.add_argument("--connect-timeout", type=float, default=5.0)
    parser.add_argument("--read-timeout", type=float, default=10.0)
    parser.add_argument("--header", action="append", default=[], metavar="K:V")
    args = parser.parse_args(argv)

    headers: dict[str, str] = {}
    for raw in args.header:
        key, sep, value = raw.partition(":")
        if not sep:
            parser.error(f"--header 需要 K:V 格式，收到: {raw}")
        headers[key.strip()] = value.strip()

    config = ProbeConfig(
        url=args.url,
        connect_timeout=args.connect_timeout,
        read_timeout=args.read_timeout,
        headers=headers,
    )
    try:
        result = probe(config)
    except ProbeError as exc:
        print(f"[error] {exc}", file=sys.stderr)
        return 1

    print(json.dumps(asdict(result), ensure_ascii=False, indent=2))
    return 0
```

### 八、常见坑速查

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| `ModuleNotFoundError: hello_world` | 没 sync / 不在项目根 / 用了系统 python | `uv sync`，再用 `uv run python -c "import hello_world; print(hello_world.__file__)"` 确认 |
| 改了 `pyproject.toml` 但 import 不到新包 | 只改声明没落地 | 跑 `uv sync`，或直接用 `uv add` |
| `attempted relative import ...` | 直接运行了包内文件 | 改用 `python -m` |
| 4xx/5xx 没有抛异常 | 忘了 `raise_for_status()` | 显式调用或判断状态码 |
| 超时设置不生效 | 把 read 当成总时长 | read 是「无新数据的最大间隔」；总时长需自己计时 |
| 重定向返回 301 | httpx 默认不跟随 | `follow_redirects=True` |
| `resp.json()` 抛 `JSONDecodeError` | 返回的是 HTML 错误页 | 先看 `status_code` 和 `content-type` |
| dataclass 可变默认值报错 | 直接写了 `{}` / `[]` | 用 `field(default_factory=dict)` |
| 测试一 import 就跑了主逻辑 | 缺 `__name__ == "__main__"` guard | 加 guard，主逻辑收进函数 |
| CI 里锁文件被偷偷改了 | 用了普通 `uv sync` | 改用 `uv sync --locked` |
